# Результат рефакторинга

## Обновление: бесплатное тестирование

По последней просьбе владельца добавлен явный тестовый режим с неизвестной выплатой/временем выплаты/открытием. В `.env` включён `OTC_TEST_MODE=true`; секреты и прежние значения сохранены. Для бесплатного тарифа без потока реализованы снимки свечей: один инструмент раз в 300 с, до 12 учитываемых API-запросов за сеанс. В сообщениях явно обозначены неизвестные данные и отсутствие live. Подтверждённое закрытие, устаревшие свечи и недостаток истории по-прежнему дают отказ. Тестовые стратегии учитываются отдельно; исходы UNKNOWN.

Журнал версии 2 хранит неизвестные payout/payout_at как NULL. Переход с версии 1 сохраняет все строки, индексы и триггеры собственной таблицы через атомарную миграцию с backup. Прошли 46 тестов, включая отправку сигнала настоящей стратегии по бесплатному снимку, неизвестную выплату, бюджет/резерв, старые свечи, повторы, строгую политику и миграцию старого журнала. Реальные API и Telegram не проверялись.

Ниже — исходный отчёт до изменения тестовой политики.

## Исходный рефакторинг

Ветка: `codex/otc-only-mvp`. Исходная точка: `6506667`. Изменения только в этом проекте; push, merge и развёртывание не выполнялись.

- Удалены прежние клиенты и сканеры, команды, новости/риски/OCR/экспорты и связанные тесты. Список зафиксирован до удаления в `audit_removal_manifest.json`.
- Сохранена общая защита одного экземпляра. База изменяется добавлением таблиц с backup перед первым обновлением существующего файла; пользовательские таблицы не удаляются. Локальных .env и баз в исходной папке не было; переменные окружения не изменялись.
- Реализованы OTC-меню, owner/callback-проверки, ограниченные сеансы, строгая проверка данных, EMA/RSI/ATR, cooldown, журнал сигналов/отказов/сравнений, виртуальная статистика, UNKNOWN, replay и последовательная проверка по отложенным окнам без настройки параметров.
- Проверены исходники установленного OTCharts 0.7.0 и документация поставщика. Использован его документированный HTTP/SSE контракт с отменяемыми async-операциями. UTC+2 преобразуется только в этом адаптере и проверяется тестами.

**Существенное ограничение:** текущий контракт OTCharts не содержит timestamp выплаты и может не подтверждать открытие Pocket Option. Адаптер блокирует live-сигналы. Нужен документированный доступ к этим подтверждениям и независимая проверка цен платформы. Платный тариф сам по себе это не исправляет. Получение ответа API не считается доказательством свежести выплаты.

Проверки: **33 теста прошли**, включая локальный HTTP/SSE сервер, реальную стратегию с синтетическими тиками, безопасную миграцию и backup, гонки start/stop, watchdog отсутствующей цены экспирации, доступ владельца, UNKNOWN и replay без будущих данных. Ruff, compileall, pip check, Git diff --check, сборка и установка wheel прошли. CLI replay и импорт сравнений проверены на временных синтетических данных. Первая попытка установки без изоляции сборки выявила отсутствие setuptools в чистом venv; штатная установка с изоляцией успешно собрала пакет.

`python main.py` проверен: при отсутствующем TELEGRAM_BOT_TOKEN выдаёт понятное сообщение и код 1. Все три необходимых локальных значения отсутствуют. Authenticated live-проверки Telegram/OTCharts, сравнение с самой платформой, демосчёт и физический Android не проверялись. Прибыльность и win rate не оценивались на реальном рынке.

Команды Windows после локального заполнения .env:

```powershell
.\.venv\Scripts\python preflight.py
.\.venv\Scripts\python main.py
```

## Исправление сетевых тайм-аутов

Устранено ложное сообщение об окончании 30-минутного сеанса при тайм-ауте HTTP-запроса. Истечение таймера проверяется через asyncio Timeout.expired(); сетевые сбои выводятся отдельно. Бесплатная проверка usage повторяется до трёх раз; отказы доступа не повторяются. До успешного чтения тарифа транспорт показывается как неопределённый. HTTP-коды доступа и квоты имеют отдельные безопасные сообщения. Прошли 52 теста, включая восстановление сети, отказ авторизации, сетевой тайм-аут и настоящий конец сеанса. Telegram-бот перезапущен; доступность данных OTCharts не подтверждена.

## XGBoost: исследовательский этап

Добавлен изолированный `services/otc_ml`: признаки EMA/RSI/MACD/ADX/ATR/Bollinger только из закрытой истории, три модели M1/M5/M15, учёт доступности исходов при разделении временных периодов, отдельные калибровка/validation/test/final holdout, выплаты ≥90%, ожидание результата с DRAW=0, сравнение с прежней стратегией на тех же возможностях, дневные блочные интервалы, отдельные критерии калибровки выбранных сигналов и контроль последних последовательных окон.

Автоматическое исследовательское переобучение поддерживается отдельным `--watch` процессом после 1000 новых проверенных примеров; старые данные проверяются по хешам, неполная запись файла не останавливает наблюдатель. Автоактивация ML и отображение вероятностей в Telegram выключены всегда. Рабочий бот и его функции не изменялись, перезапуск не требовался.

На синтетических 5400 свечах сквозной путь сохранил три модели, однако все они отклонены для практического использования. По реальным данным отчёт `awaiting_verified_data`: пригодная история не найдена. Никаких процентов реальной успешности не заявлено. Для XGBoost не нужны новые регистрации/ключи; модуль не делает сетевых запросов и не использует секреты.

Проверки: 73 локальных теста, Ruff, compileall, pip check; дополнительный CI job устанавливает опциональные ML-зависимости. Полное описание и воспроизводимые команды — ML_RESEARCH.md.

## Исправление зависшего потока

Добавлен монотонный таймер 15 с до следующего свежего допустимого тика. SSE keepalive, непрерывные старые и повторные тики не поддерживают ложную активность. При тайм-ауте генератор/HTTP-соединение закрываются, частичная свеча сбрасывается, поток переподключается с загрузкой истории. Сброс экспоненциальной задержки — после 30 с здорового потока, не одного удачного тика. Причина записывается как stream_no_fresh_ticks. Пройдены 76 тестов, включая три сценария зависания. Изменение не гарантирует доступность котировок у поставщика.

## Частота и автоматический контроль

По просьбе владельца локальная пауза между сигналами пары/экспирации уменьшена до 120 с, лимит инструментов повышен до 5 в рамках тарифа. Добавлен отдельный контроль раз в 120 с с состоянием котировок, счётчиком сигналов и причинами пропусков; недавний торговый сигнал подавляет избыточное уведомление. Контроль не выдаёт выдуманное направление. Поток по-прежнему требует свежих полных свечей и выполнения стратегии. Добавлен явный CLI-параметр запуска 30-минутного сеанса. Пройдено 82 теста, включая cooldown, уведомления и отмену контроля.

## Предварительные условные планы

Добавлен отдельный условный режим: отправка примерно за 3 минуты, точное время МСК, экспирация M1, ручная проверка цвета контрольной свечи и уровня отмены. Минимальный запас получения 120 с, ограничение отправки 10 с, один активный план на инструмент, общий cooldown 120 с, отмена при остановке/перезапуске. Новая таблица планов добавляется с backup существующей базы; исходы ручных входов не выдумываются и не смешиваются с обычной статистикой. Обычный режим сохранён. Пройдено 96 тестов, в том числе полный путь от fake-потока до предварительного плана. Реальное преимущество гипотезы не подтверждено.

## Независимое обновление каталога

Проверка тарифа/каталога вынесена из цикла чтения тиков в отменяемую фоновую задачу. Медленный REST больше не останавливает обработку потока. При ошибке обновления допуск инструментов очищается; истощение квоты останавливает сеанс. Условия стратегии не ослаблялись. Тест с зависшим ответом каталога подтверждает продолжение обработки свежих тиков и корректную отмену фоновой задачи.

## Восстановление пропущенной стартовой минуты

Исправлена блокировка стратегии после старта посередине минуты: неполная свеча не подставляется в историю, а пропуск восполняется каноническими закрытыми свечами провайдера в фоновой задаче. Незакрытые/будущие свечи отбрасываются, более новые live-бары сохраняются. Восстановление ограничено разом в минуту на инструмент и 50 запросами на сеанс с проверкой квоты; задачи отменяются при переподключении и остановке. Проверка непрерывности и пороги стратегии не изменены. Пройдено 99 тестов.
