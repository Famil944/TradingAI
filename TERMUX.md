# Запуск на телефоне и публичные отчёты

Код: ветка `main` репозитория `Famil944/TradingAI`.
Отчёты: ветка `reports`, файл `reports/termux/latest.json`.
Синхронизация не делает `git pull`, не меняет код и не загружает базу или `.env`.
По просьбе владельца отчёты публичные. В них только агрегаты виртуальных исходов,
версии стратегий, причины отсева, число подтверждений, состояния рынка и возраст
heartbeat. Нет ID чата, символов сделок, сырых логов, цен, ключей или текста API.

## Установка

Для первого запуска рекомендуется Debian внутри Termux: это обычная Linux-среда
для Python-зависимостей. Нативная установка научных библиотек на Android может
потребовать сборки. Эти команды подготовлены, но на вашем телефоне ещё не проверены.

В Termux:

```sh
pkg update
pkg install proot-distro tmux
termux-wake-lock
proot-distro install debian
proot-distro login debian
```

В Debian:

```sh
apt update
apt install -y python3 python3-venv git gh ca-certificates tmux nano
python3 --version
git clone --branch main https://github.com/Famil944/TradingAI.git
cd TradingAI
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
test -f .env || cp .env.example .env
nano .env
```

Нужен Python 3.12 или новее. В `.env` локально задайте `TELEGRAM_BOT_TOKEN`,
`OTCHARTS_API_KEY`, `OTC_ADMIN_CHAT_ID`, а для Groq — его ключ. Установите
`OTC_PRIMARY_MODE=ready` и `OTC_ML_TRAINING=false`. Не отправляйте ключи в чат или Git.
Основной и Groq работают без XGBoost. Для XGBoost нужны совместимые ML-библиотеки
и модели из локального `data/`; они намеренно не публикуются вместе с кодом.
Без них источник останется недоступен, а не начнёт выдавать выдуманные прогнозы.

## GitHub для отчётов

В Debian один раз выполните:

```sh
gh auth login --hostname github.com --git-protocol https --web
gh auth status
```

Вход выполняется на вашем устройстве. Альтернатива — fine-grained token только
для `Famil944/TradingAI`, с `Contents: Read and write`, через защищённую локальную
настройку `GH_TOKEN`. Не вставляйте токен в командную строку, URL репозитория или Git.

Сначала сформируйте и просмотрите локальную сводку:

```sh
.venv/bin/python -m services.otc_report_sync --device termux
cat data/public-report-termux.json
```

Однократная публичная загрузка и затем постоянный процесс раз в 15 минут:

```sh
.venv/bin/python -m services.otc_report_sync --device termux --upload --allow-public
tmux new-session -d -s tradingai-reports '.venv/bin/python -u -m services.otc_report_sync --device termux --upload --allow-public --watch --interval 900 >> logs/report-sync.log 2>&1'
```

Перед командой `tmux` выполните `mkdir -p logs`. При отсутствии сети процесс
повторит загрузку в следующем цикле. История сводок сохраняется в Git-коммитах.
На разных устройствах используйте разные `--device` (например `windows` и `termux`).
Запускайте только один процесс синхронизации на имя устройства. При закрытии
Termux, остановке Android или потере сети свежих отчётов не будет: проверяйте
`generated_at` и `runtime.heartbeat_age_seconds`, а не только последнюю статистику.

## Запуск бота

Сначала остановите экземпляр на компьютере. Два устройства с одним Telegram-токеном
конкурируют за polling и лимит потока. Локальная защита от второго процесса не
распространяется между устройствами. Рабочие базы при необходимости переносите
отдельно, согласованной SQLite-копией, когда бот остановлен; публичная сводка не
является резервной копией и не переносит ожидающие результаты.

```sh
mkdir -p logs
tmux new-session -d -s tradingai 'OTC_ML_TRAINING=false .venv/bin/python -u main.py --otc-session-minutes 0 >> logs/termux-bot.log 2>&1'
tail -n 30 logs/termux-bot.log
```

Сеанс: до остановки. Чтобы завершить **процесс** бота, откройте
`tmux attach -t tradingai` и нажмите Ctrl+C. Кнопка «Остановить» прекращает
сканирование, но оставляет Telegram polling работающим. Для перехода между
телефоном и компьютером необходимо завершать процесс, а не только сканирование.

Отключите оптимизацию батареи для Termux; Android всё равно может завершить
фоновый процесс. Подробности установки: [официальный Termux](https://github.com/termux/termux-app#installation).
Права GitHub: [официальная инструкция по токенам](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens).

## Как проверить позже

Откройте [отчёт телефона](https://github.com/Famil944/TradingAI/blob/reports/reports/termux/latest.json)
и попросите проверить его. Отчёт появится после первой загрузки с телефона.
Я смогу прочитать опубликованную сводку в следующем чате, но сам факт синхронизации
не запускает постоянное наблюдение с моей стороны и не даёт доступ к телефону.

Код обновляйте отдельно, с остановленным ботом: `git pull --ff-only origin main`.
Ветка отчётов не должна сливаться в код при каждом обновлении.


## Устойчивость потока OTC и проверка связи (ветка codex/otc-feed-resilience-20261119)

Изменения касаются только устойчивости получения данных и диагностики. Алгоритмы
S1–S4, сигнальные фильтры, пороги, экспирации и WIN/LOSS не изменяются.

Обновляйте ветку только после остановки работающего бота:

```sh
git switch codex/otc-feed-resilience-20261119
git pull --ff-only origin codex/otc-feed-resilience-20261119
python -m unittest tests.test_otc_feed_resilience tests.test_otc_feed_check -v
```

В обычном Termux, ДО входа в Ubuntu/Debian, выполните `termux-wake-lock`.
В Ubuntu/Debian запускайте только один экземпляр бота в `tmux`, как описано выше.
В настройках Android снимите ограничения работы Termux в фоне и экономии батареи.
Wake-lock не гарантирует, что Android или мобильная сеть не будут прерывать поток.

Быстрая локальная проверка последних 30 минут (не тратит API запросы):

```sh
python -m scripts.otc_feed_check --log logs/termux-bot.log --minutes 30
```

Если бот не сохраняет журнал, сначала запустите его с перенаправлением вывода
в файл; фоновые примеры выше уже пишут в `logs/termux-bot.log`.
Сводка отдельно считает настоящие обрывы и плановую смену пар,
показывает последние диагностические отметки и оставшуюся квоту.
Она не утверждает, что качество котировок равно точности сигналов.

Для подробностей ищите `OTC readiness gate diagnostics`,
`OTC S2-S4 candidate production diagnostics` и
`OTC per-pair tick diagnostics`. Не присылайте `.env` или ключи API.


## Отдельный фоновый тест: 30–40 секунд против обычных сигналов

Эксперимент полностью отключён по умолчанию. Он не меняет сигналы S1–S4,
которые бот отправляет пользователям. Ранние прогнозы рассчитываются теми же
функциями и проверками, но за 30–40 с до планового входа, исключительно из
уже закрытых свечей. Без новых API-запросов, дополнительного потока или ставок.
Отдельные будущие исходы не являются подтверждёнными сделками Pocket Option.

На телефоне сначала завершите процесс бота (а не только остановите сеанс).
После обновления ветки `codex/otc-only-mvp` добавьте в локальный `.env`:

```dotenv
OTC_EARLY_SHADOW_ENABLED=true
```

Перезапустите тот же бот, запустите обычный OTC-сеанс M2/M5/M15.
Ранние прогнозы НЕ отправляются в Telegram, не считаются в обычном винрейте
и сохраняются в отдельной базе `data/early-lead-30-40.db`. Удалять базу
нельзя, если нужна статистика сравнения. Основная рассылка работает как прежде.

Посмотреть сравнение прямо в Telegram: `/lead_compare` (только владелец).
Или вывести локально за последние 7 дней:

```sh
python -m services.otc_early_lead --report --days 7
```

Отчёт показывает количество ранних и доставленных обычных прогнозов,
винрейт WIN/(WIN+LOSS), совпадения инструментов/времени и сравнение результатов
только там, где обе стороны имеют подтверждённый исход. DRAW, UNKNOWN и PENDING
не входят в винрейт. Малое число совпадений — не доказательство преимущества.

Для остановки эксперимента поменяйте строку на
`OTC_EARLY_SHADOW_ENABLED=false` и перезапустите процесс. Собранные данные
при этом сохраняются. Не запускайте вторую копию бота с тем же токеном.


## Голосования: проценты и кто проголосовал

В личном чате подписчика после голосования показываются проценты по каждому
варианту и число голосов. Кнопка «Обновить результаты» позволяет получить
актуальные проценты без повторного голосования; свой выбор можно менять.
Голос подписчика сохраняется в `data/announcements.db`: один выбор на
одного пользователя в каждом опросе. Изменение выбора заменяет старый голос.

Владелец: /announce → «История и результаты» → нужный опрос →
«Кто как проголосовал» или «Кто ещё не ответил». Отчёты показывают
сохранённый выбор, имена/@username из уже имеющихся профилей подписчиков
и Telegram ID; для не имеющих профиля отображается ID.
Список «не ответил» включает только адресатов с успешной отправкой.
Обычным подписчикам персональные данные других голосующих не показываются.
В тексте нового опроса подписчики заранее предупреждаются, что владелец
может видеть их выбор. Ранее опубликованные опросы сохраняют прежние голоса
и доступны в истории без миграции; для новых процентов следует нажать
старый вариант ответа либо новую кнопку обновления после взаимодействия.

Публичный винрейт, OTC-сигналы, подписки и виртуальные средства не затронуты.


## Включение фонового сравнения одной командой через Termux

Войдите в установленную Ubuntu или Debian через Termux, перейдите в папку
`~/TradingAI` и **остановите работающий процесс** перед обновлением кода.
Не запускайте второй экземпляр с тем же Telegram-токеном.

```sh
git switch codex/otc-only-mvp
git pull --ff-only origin codex/otc-only-mvp
python -m scripts.configure_early_shadow --enable
```

Команда обновляет только `OTC_EARLY_SHADOW_ENABLED` в существующем локальном
`.env` атомарно, сохраняет все остальные ключи и права доступа. Если файла
`.env` нет, команда откажется создавать неполную конфигурацию. Ключи не выводятся.
После этого запустите бот обычным способом и обычный OTC-сеанс.

Для проверки: `/lead_compare` в Telegram (только владелец).
Для выключения на телефоне: `python -m scripts.configure_early_shadow --disable`,
затем перезапустите бот. Изменение не влияет на основные S1–S4 и не отправляет
ранние прогнозы подписчикам; отдельная база находится в
`data/early-lead-30-40.db`.

Если переменная `OTC_EARLY_SHADOW_ENABLED` отдельно задана через shell или
tmux, она имеет приоритет над `.env`; сначала удалите такое переопределение.


## Отдельный винрейт фонового анализа 30–40 секунд

Фоновый анализ имеет независимую статистику и отдельную базу
`data/early-lead-30-40.db`. Его результаты не влияют на основной винрейт,
рассылку пользователям и торговые стратегии S1–S4.

У владельца в OTC-меню: «🧪 Фоновый WR» → 7 дней / всё время.
Команда `/shadow_winrate` показывает такой же отчёт. Кнопка
«⚖️ Сравнить» открывает старое сопоставление основного и раннего времени.
В отчёте: общий WR и отдельно S1–S4 по M2/M5/M15, количество WIN, LOSS,
PENDING, DRAW, UNKNOWN. WR учитывает **только** подтверждённые WIN и LOSS;
остальные исходы видимы, но не входят в знаменатель.

## Экспирации сигналов — личная настройка подписчика

В личном меню «🎛 Мои сигналы» добавлены переключатели ✅/❌ M2, M5 и M15.
Подписчик может оставить только M2 или любое другое сочетание. Все три
экспирации включены по умолчанию, чтобы не менять существующий опыт.
Выбор хранится в `data/subscribers.db` и сохраняется после перезапуска.
Отключённые экспирации не доставляются **как новые сигналы** только данному
подписчику. Уже полученные сообщения могут получить окончательный WIN/LOSS,
чтобы не оставлять старые циклы без результата. Сеансовые ограничения,
доступ и выбор стратегий остаются отдельными настройками.

Обратите внимание: это управление рассылкой, не изменение условий
формирования прогнозов и не способ повысить их точность.


## H1: часовой прогноз только в фоновом режиме

Дополнительный H1 входит в тот же опциональный эксперимент
`OTC_EARLY_SHADOW_ENABLED=true`. Сигнал фиксируется за 5 минут
до начала очередной часовой свечи — на интервале примерно 04:45–05:00
минут до ближайшего часа (например 12:55:00–12:55:15 для входа в 13:00).
Смысл: направление новой H1 свечи от её открытия до закрытия ровно через час.

Для H1 используется 1 попытка, **без догонов**. Только 1 H1-кандидат
на час для фонового исследования; выбор S1/S2/S3/S4 заранее фиксирован
по приоритету, не по будущим результатам. Для первого метода требуются
минимум 20 полноценных H1 свечей, для S2–S4 — 60 непрерывных часов.
История читается из уже имеющегося локального архива M1, без новых запросов
OTCharts. Если истории не хватает, сигнал H1 не создаётся, пропуск не заменяется
догадкой. Особенно после первого запуска или ротации пар H1 может молчать.

В Telegram у владельца «🧪 Фоновый WR» отдельно показывает H1 WIN/LOSS/WR
рядом с M2/M5/M15. H1 никогда не отправляется подписчикам и не изменяет
боевую рассылку S1–S4, правила винрейта и торговые ограничения.
WIN/LOSS — только по наблюдениям OTCharts. При отсутствии цены
открытия/закрытия статус остаётся PENDING, потом UNKNOWN.
Данные сохраняются в `data/early-lead-30-40.db`.
