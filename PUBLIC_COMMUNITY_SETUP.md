# TradingAI — открытая статистика и предложения

Рабочая ветка: feat/public-cycles-feedback-20261117 (от codex/otc-only-mvp).
Используются M2/M5/M15. Модуль личного виртуального счёта и логика
основных прогнозов не редактировались. Основная ветка main не менялась.

## Возможности
- /start: личное административное меню владельца, публичное меню для подписчиков.
- /signal_stats: три независимых вида статистики:
  A — отдельные завершённые попытки, B — сигналы ×3, C — циклы ×6.
- Отдельные версии, экспирации и стратегии. Фоновые стратегии отмечены «ТЕСТ»
  и не выдаются за реально доставленные торговые сигналы.
- /suggest: предложение пользователем в личном чате, без публикации.
- /suggestions: приватная очередь владельца, статусы и ответы через бота.
- Telegram-канал: уведомления и отчёты каждые 10 подтверждённых результатов
  по стратегиям, версиям, экспирациям и метрикам. По умолчанию выключен.

## Настройка Telegram-канала
1. Создайте отдельный канал и дайте боту права на публикацию и редактирование.
2. Получите числовой chat_id канала, начинающийся с -100.
3. Добавьте в ЛОКАЛЬНЫЙ .env строку:
   OTC_PUBLIC_CHANNEL_ID=-1001234567890
4. Перезапустите только один экземпляр бота с этим токеном.
5. Старая история не републикуется; новые сигналы публикуются после запуска.

Три фоновые исследовательские стратегии по умолчанию доступны для просмотра
в меню статистики. Публикацию фоновых тестовых прогнозов в канал при желании
включают отдельной строкой в локальном .env:
OTC_PUBLIC_SHADOW_METHODS=bb_reentry,break_retest,ema_pullback

Публикации фоновых прогнозов обязательно маркируются «ТЕСТ», не как
подтверждённые сделки на Pocket Option.

## Приватность
Публичные сообщения формируются только из разрешённых полей: названия
стратегии, пары, времени, направления, экспирации и исходов.
Личный виртуальный счёт, его баланс, ставки и причины пропуска не читаются
и не публикуются новыми средствами. Прежние приватные сообщения не меняются.
Канал отключён, пока ID не указан явно.

Доставка через Telegram не может гарантировать абсолютное exactly-once
при потере подтверждения на сетевом уровне. Журнал подтверждённых
отправлений хранится отдельно в data/public-telegram.db.
Обратная связь хранится в data/community-feedback.db.

## Исторические отчёты
В папке с локальными базами данных запустите:
python -m scripts.recover_otc_history --root . --output data/exports

Создаются signals.csv и daily.csv (разные A/B/C, дни, версии, экспирации).
Результаты «UNKNOWN» остаются неподтверждёнными. Никаких денежных значений
или данных личного виртуального счёта в экспорт не включается.
GitHub не хранит автоматически файлы баз данных с Windows и Termux.
Для полноценного восстановления старых запусков нужны доступные локальные
базы/логи именно с этих устройств.

## Правила ×6
Два последовательных сигнала ×3 одной версии стратегии, источника
и экспирации могут образовать один статистический цикл ×6. Следующий
сигнал должен появиться после подтверждения полного LOSS первого.
Допустимое ожидание второго — 2 часа. Позднее цикл INCOMPLETE.
Показатели A/B/C самостоятельные; WIN ×6 не означает денежную прибыль.

## Безопасное обновление Termux после слияния PR

Используйте ветку codex/otc-only-mvp (бот M2/M5/M15), а не main
(старый интерфейс M1/M5/M15). Не запускайте обе версии одновременно
с одним Telegram токеном.

Сначала остановите старый экземпляр штатной кнопкой и сохраните файлы.
В Termux, из папки проекта:

    cd ~/TradingAI
    git branch --show-current
    git status --short
    mkdir -p "$HOME/tradingai-backups"
    tar -czf "$HOME/tradingai-backups/data-$(date +%Y%m%d-%H%M%S).tgz" .env data

Если команда tar сообщает об отсутствующем файле, проверьте путь и
не продолжайте переключение ветки, пока не сделана копия существующих
данных. Не публикуйте архив, поскольку он содержит секреты и личные базы.

После успешного резервного копирования:

    git fetch origin
    git switch codex/otc-only-mvp || git switch --track origin/codex/otc-only-mvp
    git pull --ff-only
    python -m pip install -r requirements.txt
    python -m unittest tests.test_otc_public_community -v
    python main.py

Выполните сначала проверку /start и /signal_stats в Telegram.
Сообщение «ОСНОВНОЙ» не должно содержать ставки или баланс в публичном
канале. Затем проверьте /suggest с другого Telegram-аккаунта.
Не публикуйте и не включайте общий канал до проверки на личном чате.

### Windows / VS Code

    python -m pip install -r requirements.txt
    python -m unittest tests.test_otc_public_community -v
    python -m scripts.recover_otc_history --root . --output data/exports

Локальные базы Windows нельзя восстановить из одного Git-репозитория.
Экспорт делает **неизменяющее** чтение журнальных файлов. Он не создаёт
несохранённые сигналы и не заменяет UNKNOWN результатами без доказательств.

### Очередь отчётов

Отчёты A/B/C составляются из устойчивой очереди только завершённых
WIN/LOSS. Позднее уточнение старого UNKNOWN не пересобирает десятку,
уже опубликованную в Telegram. По-прежнему невозможно гарантировать
отсутствие дублей при сетевой потере ответа Telegram между успешной
отправкой и записью ID сообщения: для этого нужна дополнительная сверка.
Временно отключённая фоновая стратегия при повторном включении
начинает публикации с нового момента, а не рассылает старую историю.

## Что нельзя считать проверенным без устройства пользователя

- Получение сигналов по текущим данным OTCharts и совпадение с Pocket Option.
- Старые запуски VS Code и Termux без предоставления локальных журналов.
- Публикация в реальный канал и работа кнопок в настоящем Telegram.
- Прибыльность любой стратегии или достижение определённого винрейта.

Любые значения WR — только результаты наблюдаемых модельных прогнозов,
не доходность и не исполненные брокером сделки.


## Подписчики: автоматические сигналы и отдельные меню

Telegram-бот показывает **разные команды** владельцу и обычным пользователям.
Владелец по-прежнему видит /otc, /otc_stats, /otc_research и свои кнопки
запуска/остановки. У подписчиков в списке команд остаются только:
- /start — подключить получение новых сигналов в личном чате;
- /help — справка;
- /signal_stats — статистика прогнозов и фоновых стратегий;
- /suggest — предложить улучшение;
- /stop_signals — отключить личную рассылку.

Кнопка запуска торгового сеанса подписчикам не отображается и недоступна
серверно. Только владелец с OTC_ADMIN_CHAT_ID может запускать и останавливать
основную работу. Команда /start пользователя **не** запускает сканирование,
а только сохраняет согласие на отправку новых сигналов.

После того как пользователь один раз открыл личный чат с Telegram-ботом
и отправил /start, новые сигналы Боллинджер ×3 приходят ему автоматически,
включая обновления доступных результатов. Старые сигналы не досылаются как
новые. Публикуются только разрешённые поля прогноза без данных личного
виртуального счёта.

Подписчики, которые нажимали /start в старой версии, должны нажать /start
после обновления хотя бы раз: Telegram Bot API не предоставляет список
старых пользователей, а ранее согласие не сохранялось.

Канал работает независимо: пользователь, вступивший в Telegram-канал,
получает сообщения канала от Telegram и не обязан писать боту. Но для
публикации в канале по-прежнему необходимо установить
OTC_PUBLIC_CHANNEL_ID и выдать боту необходимые права.

Хранилище личных подписок: data/subscribers.db. Рядом хранятся ID
отправленных сообщений и их версии; повторный запуск не должен
дублировать успешно подтверждённые отправки. При сетевой потере ответа
Telegram полной гарантии exactly-once нет. При запрете личных сообщений
бот автоматически выключает недоступную подписку.

Пока владелец не запустил торговый сеанс и не появился новый сигнал,
подписчики ничего нового не получат. Кнопка /start лишь активирует
уведомления, а не создаёт торговые прогнозы.

В интерфейсе Telegram на некоторых устройствах старые команды могут
кэшироваться до перезапуска чата/приложения. После перезапуска бота
публичный список будет заменён на разрешённый. Для доставки на большое
число подписчиков предпочтительнее Telegram-канал: личная рассылка
требует отдельного запроса Telegram API каждому пользователю и не
гарантирует одинакового времени получения при большом числе адресатов.
